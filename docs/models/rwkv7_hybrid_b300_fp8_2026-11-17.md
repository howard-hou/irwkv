# RWKV-7 Hybrid FP8 初步测试与后续研究交接（2026-11-17）

## 结论

- 在同一台 B300 上复现了 bux 的 KDA 和 RWKV-7 dummy-weight agentic 负载。
- KDA 的 SLO 内最佳点为 **2185.5 sessions/h @ c40**，公开记录为 2165 @ c40，差约 **+0.95%**。
- bux/RWKV-7 的 SLO 内最佳点为 **1781.7 sessions/h @ c32**，公开记录为 1771 @ c32，差约 **+0.61%**。
- B300 的 irwkv 运行未设置 `IRWKV_RWKV_HYBRID_RECURRENT_BACKEND=albatross`，因此全部是 **FlashRWKV2＋full-decode graph**，不包含 Albatross 的 shift、kk-pre/post 融合及 state 直接读写。原始 FP8 路径为 **381.1 sessions/h @ c8**，Cutlass FP8 GEMM 为 **395.9 sessions/h @ c8**，提升约 **3.9%**；这只是该后端与编译配置的 A/B，不是 irwkv 最优性能结论。
- 后续 RTX PRO 6000 SM120 同机测试已跑通实验性 FlashRWKV2 Inductor＋full/piecewise graph 路径，并完成 c8/c16/c32 原始负载。RTX 数字不得与 B300 数字直接作硬件无关的优劣比较。
- 默认 eager＋full-decode graph 现已固定为 Albatross，FlashRWKV2 eager decode 入口和后端环境开关已删除。显式 Inductor 仍使用独立的 FlashRWKV2 编译路径，不包含 Albatross decode 融合；历史数据继续按实际路径分开记录。
- 所有权重都是 dummy weights。这些结果只用于吞吐对比，不是训练模型精度、FP8 质量、编译前后逐 token 等价或 Albatross 数值对齐证明。

核心数值另存于 `rwkv7_hybrid_b300_fp8_2026-11-17.jsonl`。JSONL 去掉了每行重复的 model/load 字段，负载和模型配置以本文为准；文件名保留 `b300` 是为了维持既有交接链接，其中也包含明确标记的 RTX 结果。

## RTX PRO 6000 SM120 同机 A/B

环境为 NVIDIA RTX PRO 6000 Blackwell Server Edition（97887 MiB，SM120）、Runpod US-PA-1、同一 PyTorch 2.13.0+cu132 镜像、FlashRWKV2 0.1.0a19 和 vLLM 0.32.0。模型、dummy weights、完整 agentic 负载、Cutlass FP8 GEMM、FP8 KV、SLO 与 `max_num_seqs=128` 均保持一致。这里的对照只用于同机软件路径 A/B，不与上面的 B300 数值直接比较。

| recurrent／编译路径 | 并发 | sessions/h | output tok/s | p50 TPOT ms | p50 TTFT s | 首轮 p50 TTFT s | cache hit |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| FlashRWKV2，eager＋full-decode graph | 8 | 293.1 | 166.7 | 38.01 | 1.329 | 9.908 | 74.10% |
| FlashRWKV2，eager＋full-decode graph | 16 | 389.8 | 221.7 | 54.66 | 1.483 | 13.232 | 74.25% |
| FlashRWKV2，Inductor＋full/piecewise graph | 8 | 1135.6 | 646.0 | 10.45 | 0.285 | 2.238 | 74.10% |
| FlashRWKV2，Inductor＋full/piecewise graph | 16 | 1862.4 | 1059.5 | 11.72 | 0.291 | 2.390 | 74.25% |
| FlashRWKV2，Inductor＋full/piecewise graph | 32 | 2755.6 | 1567.7 | 14.06 | 0.340 | 2.450 | 74.29% |
| FlashRWKV2，Inductor＋full/piecewise graph | 64 | 1272.2 | 723.7 | 51.83 | 17.794 | 16.380 | 9.72% |

c8 同机对比中，Inductor 吞吐为默认路径的 **3.87×**，p50 TPOT 从 38.01 ms 降至 10.45 ms（**3.64×** 改善），首轮 p50 TTFT 从 9.908 s 降至 2.238 s（**4.43×** 改善）。c16 吞吐为 **4.78×**，TPOT 从 54.66 ms 降至 11.72 ms（**4.66×** 改善），首轮 TTFT 从 13.232 s 降至 2.390 s（**5.54×** 改善）。默认路径在 c16 已超过 SLO，未继续其 c32/c64/c128。

Inductor 的 c32 是此次扫描 SLO 内最佳点。c64 的 cache hit 从低并发约 74% 降至 9.72%，TPOT 超过 SLO，扫描按规则停止，没有 c128 结果，不能将低并发收益线性外推。

c64 已有明确的容量触发条件：编译路径 KV 容量为 `5558 * 144 = 800352` tokens，c64 仅首轮 64 份 16384-token 上下文就需要 `1048576` tokens；c32 对应需求为 524288 tokens，可以容纳。这与高并发 cache hit 崩塌一致，但具体驱逐、抢占和调度过程仍需 trace 证实，不能仅凭容量算术断定全部原因。

## Inductor 修复与 SM120 验证

bux 的实现将 token shift、recurrence 和 attention 作为编译图边界，让投影、FFN 和量化等纯张量计算进入 Inductor。irwkv 默认仍是 `CompilationMode.NONE`＋full-decode graph，本节的 Inductor 是显式开启的实验路径，且仅支持 FlashRWKV2。

已定位并修复的兼容性问题：

1. 为模型增加 `support_torch_compile`，避免引擎静默跳过编译。
2. 为 `irwkv7_albatross::layer_norm` 增加 fake/Meta 实现。
3. 将扩展加载和 fake 注册拆开：`_load_albatross()` 只加载扩展；`_register_albatross_fakes()` 在 cache 初始化、Dynamo 追踪之前注册，避免 forward 中调用被跳过的 `torch.library.register_fake`。
4. 增加 shift、recurrence、attention 三个自定义 op 及 splitting 边界，保留 scheduler-owned state 和 paged KV 的更新语义。
5. 默认 Albatross decode 与实验 Inductor 不混用；只有显式开启 Inductor 时才选择其 FlashRWKV2 编译路径，默认 eager 测试没有 FlashRWKV2 decode 回退。

小型完整引擎负载已跑通 FP8 weights＋FP8 KV、prefix caching、chunked prefill 和四轮生成：Inductor 编译 18.27 s，FULL/PIECEWISE 图均完成捕获，cache hit 42.86%，p50 TPOT 2.13 ms。3584 模型 Dynamo 为 19.88 s，完整 Inductor 编译为 124.47 s，19 档 FULL/PIECEWISE CUDA Graph 捕获成功；这些是实际完成负载，不是仅启动引擎。

## 动态 FP8 量化诊断

vLLM `scaled_fp8_quant(..., use_per_token_if_dynamic=True)` 可作为后续优化候选，但不能直接无验证替换：

- 普通随机 BF16 输入：FP8 量化值与现有实现完全一致，dequant 最大误差为 0。
- 全零输入：dequant 输出仍一致，但 kernel 的最小 scale 与现有 `1e-12` 约定不同。
- 全 `1e-12` 输入：512/512 个 FP8 值不同，dequant 最大绝对差约 `1.0e-12`。

因此当前 Cutlass 补丁没有改动态量化语义。若采用融合量化，需要明确处理边界行为并补充对应测试。

## 后续研究优先级

1. **补数值等价验证**：对默认与 Inductor 路径做同一输入的逐 token 对比，并在真实训练权重上评估 FP8 质量；当前 dummy-weight 负载成功不构成精度证明。
2. **补齐后端组合**：在 B300 上重跑 Albatross＋full-decode graph，并研究 Albatross 融合 decode 与 Inductor 的组合；不要把 FlashRWKV2 数字当成 Albatross 数字。
3. **诊断 c64 cache hit 崩塌**：核查缓存容量、驱逐、抢占及 prefix 复用，解释 74% 到 9.72% 的变化后再优化高并发。
4. **分别记录 prefill 和 decode 收益**：同时观察冷启动首轮 TTFT、后续 TTFT、TPOT 和吞吐，不能只优化其中一个。
5. **保留 Cutlass 作为独立 A/B**：B300 FlashRWKV2 路径上只有约 3%–4% 吞吐收益，它不是 Inductor 大幅收益的替代解释。
6. **不要把合并 RWKV r/k/v 当成已证实方向**：bux 同样分开 r/k/v 投影；既有 A100 trace 也显示 GEMM、attention 和 host/copy overhead 都需要分析。
