# RWKV-7 Hybrid FP8 初步测试与后续研究交接（2026-11-17）

## 结论

- 在同一台 B300 上复现了 bux 的 KDA 和 RWKV-7 dummy-weight agentic 负载。
- KDA 的 SLO 内最佳点为 **2185.5 sessions/h @ c40**，公开记录为 2165 @ c40，差约 **+0.95%**。
- bux/RWKV-7 的 SLO 内最佳点为 **1781.7 sessions/h @ c32**，公开记录为 1771 @ c32，差约 **+0.61%**。
- B300 的 irwkv 运行未设置 `IRWKV_RWKV_HYBRID_RECURRENT_BACKEND=albatross`，因此全部是 **FlashRWKV2＋full-decode graph**，不包含 Albatross 的 shift、kk-pre/post 融合及 state 直接读写。原始 FP8 路径为 **381.1 sessions/h @ c8**，Cutlass FP8 GEMM 为 **395.9 sessions/h @ c8**，提升约 **3.9%**；这只是该后端与编译配置的 A/B，不是 irwkv 最优性能结论。
- 后续 RTX PRO 6000 SM120 同机测试已跑通实验性 FlashRWKV2 Inductor＋full/piecewise graph 路径，并完成 c8/c16/c32 原始负载。RTX 数字不得与 B300 数字直接作硬件无关的优劣比较。
- 默认 eager＋full-decode graph 仍固定为 Albatross。当前开发分支恢复了仅作用于 Inductor 的后端开关，可用同一套纯张量编译和 CUDA Graph 外围路径对比 Albatross 与 FlashRWKV2；历史数据继续按实际路径分开记录。
- 当前 B300 Inductor A/B 的 SLO 内最佳点均为 **c64**：Albatross 为 **7692.8 sessions/h、9.63 ms p50 TPOT**，FlashRWKV2 为 **7682.1 sessions/h、9.67 ms**；c8–c64 差异很小且没有一致领先方。c128 两端均因 cache hit 降至 33.00% 而超过 SLO。
- **d3584 的 KDA 与 irwkv 数字是两套完整优化实现的同宽端到端参考，不是博客目标曲线的答案。** 两者的层数、宽度、FP8、MLP 和 Attention 架构语义已对齐，但 KDA 原生参数更多，且各自使用不同的 mixer、Attention kernel 和执行栈。不能仅用这一点的“约 3.5×”比值替代多宽度测量与 1,924 sessions/h 插值。
- **同宽不等于同参数规模。** 本次 d3584 的 bux KDA 为 **10.861B active／11.041B total**，bux RWKV-7 和 irwkv 均为 **8.713B active／8.893B total**；KDA 的 active 参数多 **24.65%**。此前只核对 width、层数和 vocab 是不充分的，但不存在 irwkv 的 RWKV-7 导出尺寸错误。
- 所有权重都是 dummy weights。这些结果只用于吞吐对比，不是训练模型精度、FP8 质量、编译前后逐 token 等价或 Albatross 数值对齐证明。

核心数值另存于 `rwkv7_hybrid_b300_fp8_2026-11-17.jsonl`。JSONL 去掉了每行重复的 model/load 字段，负载和模型配置以本文为准；文件名保留 `b300` 是为了维持既有交接链接，其中也包含明确标记的 RTX 结果。

### 与博客、serving 文档及原始 lanes 对齐

三个导出均为 width 3584、56 层、vocab 50304、dummy weights，采用 3 个 linear mixer＋1 个全注意力层的重复布局，即 42 个 linear 层和 14 个全注意力层。相同 scaffold 不表示参数相同：`mixers.bux` 的 KDA 使用 `d_model // 128` 个 query/key heads、两倍 value heads、`head_dim=128`；RWKV-7 使用 `d_model // 64` 个 heads、`head_dim=64`。

| 对象 | 原始 family／arm | total 参数 | active 参数 | recurrent state／session | weights |
| --- | --- | ---: | ---: | ---: | ---: |
| bux KDA d3584 | `control/kda+fp8`／`mixers[kda]` | 11,041,100,336 | 10,860,810,800 | 81,887,232 B | 10.46 GiB |
| bux RWKV-7 d3584 | `mixers/rwkv7+fp8`／`mixers[rwkv7]` | 8,893,208,576 | 8,712,919,040 | 19,568,640 B | 8.45 GiB |
| irwkv RWKV-7 d3584 | 本地导出核对 | 8,893,208,576 | 8,712,919,040 | 未在此单列 | 未在此单列 |

KDA 比 RWKV-7 多 2,147,891,760 个 active 参数，即 **24.6518%**；其每 session recurrent state 是 RWKV-7 的 **4.1846×**。这是两种 mixer 原生形状造成的差异，不是把 irwkv 错导成了另一个尺寸。

两份公开材料中的数字必须按以下口径阅读：

1. 博客的“KDA 3/4 可承载 **13.3B active**、RWKV-7 可承载 **8.0B active**”对应 serving 表的 `mixers/kda+fp8`（d3830，13.3B）与 `mixers/rwkv7+fp8`（d3479，7.97B）。它们是在 **1,924 sessions/h／GPU** 相同 FP8 预算下，对相邻实测宽度做 log-log 插值得到的 target，**不是本次 d3584 实例的参数量**。
2. serving 表的 `control/kda+fp8` 是另一个汇总 family，target 为 d3782、12.8B active；其原始 lane 的 `arm=mixers[kda]` 确认了本次复现对象。该 target 与博客的 13.3B 属于不同 family／sweep 的拟合结果，不能替代原始 d3584 lane 的 10.861B。
3. 博客另有“2026 KDA hybrid **11.4B active／201B total**”，指加入 gated GQA、QK-norm、fine-grained MoE、MTP 等改动的 `m2026_hybrid`，不是本次只替换 mixer 的 KDA 对照。
4. serving 表每个宽度选取 **p50 TPOT ≤ 30 ms 内最高的 sessions/h／GPU**，不是固定并发比较。例如公开 RWKV-7 d3584 c40 虽为 1,922.4 sessions/h，但 p50 TPOT 31.64 ms 超限，所以表中 SLO 内最佳值是 **1,771 @ c32**。
5. 原始 FP8 口径是 vLLM online per-tensor FP8 linear＋FP8 KV cache；embedding、lm_head、norm、conv 和 recurrent states 保持默认精度，并非整网 FP8。irwkv 的自定义量化与后端边界仍需单独核对，不能因命令都有 `fp8` 就视为实现一致。

因此，对照应保持同一 scaffold、宽度、层数、精度、MLP 与 Attention 架构语义，允许两种 mixer 的原生参数量和各自实现不同；**不做等 active 参数对照**。irwkv 作为独立完整实现直接参与测量，不再要求共用 bux 的 Python 类、Attention kernel 或 serving 执行栈。

### 最终目标：重绘 `Hybrids: SWA vs Linear Attention`

目标不是比较同宽 KDA／irwkv 的端到端倍数，而是复现并更新博客该图的 **serving target**：在 1,924 sessions/h／GPU、p50 TPOT ≤ 30 ms 的相同预算下，RWKV-7 能承载多少 active 参数。

原始 RWKV-7 的 8.0B 可由公开 lanes 精确还原：

| width | active 参数 | SLO 内最佳 sessions/h | 并发 | p50 TPOT |
| ---: | ---: | ---: | ---: | ---: |
| 3328 | 6,981,042,432 | 2,178.1 | 40 | 28.08 ms |
| 3584 | 8,712,919,040 | 1,770.9 | 32 | 27.29 ms |

在 log sessions/h 与 log active parameters 之间对预算 1,924 做线性插值，得到 **7,972,687,279 active（7.9727B）**，与 serving 表的 d3479、7.97B 及博客四舍五入后的 8.0B 一致。因此，**8.0B 是原始 bux 实现和测量曲线的内部一致结果，不是图表计算错误；要更新它，必须改变实现并重新测量曲线。**

源码边界也需要准确描述：`bux_vllm.rwkv7.Mixer` 复用 `Recurrent`。在安装 FLA 且模型为 BF16／FP16 时，prefill／decode 优先使用 FLA DPLR kernels；没有可用 DPLR 时才退回 `bux_vllm.delta` 的 PyTorch 实现。KDA 则走其专用 KDA kernels。本次环境记录了 FLA 0.6，原始 RWKV-7 基线应按 FLA DPLR 处理，并在后续 trace 中确认实际调用。

重绘采用独立模型、相同实验条件的路线：

1. **不把 irwkv 接入 bux，也不增加任何 bux 适配层。** bux 负责 KDA 与原始 RWKV-7 参考；irwkv 直接加载自己的模型配置，使用自己的完整优化 RWKV-7 mixer、serving 栈和 CUDA Graph。
2. **对齐模型外部架构与测量条件。** 每个 RWKV-7 测量点与 bux 使用相同 width、层数、vocab、总／active 参数公式、3:1 recurrent／attention 布局、FP8 weights＋FP8 KV、pre-LayerNorm、biased 4D GELU MLP，以及带 bias QKV/O、head size 64、half-layout RoPE 的全注意力层。recurrent state 属于 mixer 自身，不要求与 KDA 相同。
3. **只要求 Attention 和 MLP 的架构／数学语义一致，不要求共用 Python 类或底层 kernel。** irwkv 保留自己的 FA4 FP8 paged attention、在线 FP8、Inductor 和其他优化；不再把“共同层必须使用 bux 的执行栈”作为前置条件。负载、硬件、并发扫描、prefix caching、SLO 与统计口径保持一致。
4. **直接测完整优化实现的曲线。** 原始 `bux FLA DPLR = 7.97B` 是公开参考；d3584 的 irwkv 结果是新实现的第一个测量锚点，不需要先重跑 bux adapter 或做 FLA DPLR／Albatross 后端替换实验。
5. **重新测量多宽度曲线。** 从 d3584 向更宽方向寻找 1,924 sessions/h 的上下 bracket，至少取得两个 bracketing widths，优先 3–4 个邻近宽度检查插值敏感性；每个宽度仍扫描并发并选取 SLO 内最佳点，不能挑选单个高吞吐点。
6. **目标图使用 `RWKV-7 (irwkv optimized)` 的新实测 target。** 可同时保留原始 `bux FLA DPLR = 7.97B` 作为参考，其他 architecture arms 沿用原始 bux 数据，图注明确各模型的实现版本。
7. **若重绘完整三联图，还要更新 Predicted。** Measured 面板不变；Serving 使用新 target；Predicted 需将原 scaling law 在新 active target 和 1T tokens 处重新求值，不能只替换 8.0B 文本。

在新曲线完成前，不预先填写新的 RWKV-7 serving target，也不用 d3584 的单点 irwkv／KDA 比值代替多宽度曲线。

统一负载：

- shared prompt 2048 tokens，session 私有上下文 14336 tokens；
- 4 turns，每轮 512 output tokens，轮间 2048 tool tokens；
- prefix caching，`max_num_batched_tokens=16384`，`max_model_len=32768`；
- FP8 weights + FP8 KV；TP=1；seed=0；
- 并发扫描 `8,16,32,64,128`，每个并发运行 `2 * concurrency` 个 session；
- p50 TPOT SLO 30 ms，超限停止；原复现扫描使用 `--refine 2`；
- KDA/bux 使用其默认 B300 attention，不强制 Triton。

## B300 `c4cfbaf` 复测（EUR-IS-1）

复测实例为 Runpod EUR-IS-1 的 NVIDIA B300 SXM6 AC（SM103，275040 MiB），实际费率为 **8.99 美元／小时**，镜像和软件版本与前述环境一致。默认路径结果使用 `c4cfbaf` 独立源码快照；其后的双后端 Inductor A/B 使用明确标记的工作树补丁。两者统一负载及 dummy weights 不变。

Albatross eager 在 c8 为 313.5 sessions/h，相对 FlashRWKV2 eager 的吞吐为 **1.07×**，TPOT 从 38.01 ms 降至 34.85 ms，首轮 TTFT 从 9.908 s 变为 9.907 s，基本没有 prefill 改善。它在 c8 已超过 SLO，因此未继续 c16 及更高并发。

以 FlashRWKV2 eager 为基线，Inductor 在 c8 的吞吐为 **3.87×**，p50 TPOT 从 38.01 ms 降至 10.45 ms（**3.64×** 改善），首轮 p50 TTFT 从 9.908 s 降至 2.238 s（**4.43×** 改善）；c16 吞吐为 **4.78×**，TPOT 从 54.66 ms 降至 11.72 ms（**4.66×** 改善），首轮 TTFT 从 13.232 s 降至 2.390 s（**5.54×** 改善）。FlashRWKV2 eager 在 c16 已超过 SLO，未继续其 c32/c64/c128。

c64 已有明确的容量触发条件：编译路径 KV 容量为 `5558 * 144 = 800352` tokens，c64 仅首轮 64 份 16384-token 上下文就需要 `1048576` tokens；c32 对应需求为 524288 tokens，可以容纳。这与高并发 cache hit 崩塌一致，但具体驱逐、抢占和调度过程仍需 trace 证实，不能仅凭容量算术断定全部原因。

## 动态 FP8 量化诊断

vLLM `scaled_fp8_quant(..., use_per_token_if_dynamic=True)` 可作为后续优化候选，但不能直接无验证替换：

- 普通随机 BF16 输入：FP8 量化值与现有实现完全一致，dequant 最大误差为 0。
- 全零输入：dequant 输出仍一致，但 kernel 的最小 scale 与现有 `1e-12` 约定不同。
- 全 `1e-12` 输入：512/512 个 FP8 值不同，dequant 最大绝对差约 `1.0e-12`。

因此当前 Cutlass 补丁没有改动态量化语义。若采用融合量化，需要明确处理边界行为并补充对应测试。

## 后续研究优先级

1. **补数值等价验证**：优先定位 B300 FA4 FP8 回归中 7／320 个元素超差的问题；再对默认与 Inductor 路径做同一输入的逐 token 对比，并在真实训练权重上评估 FP8 质量。当前 dummy-weight 负载成功不构成精度证明，不能通过放宽断言掩盖数值失败。
2. **解释 Inductor 后端持平**：用重复运行和 kernel timeline 分离 recurrent、GEMM、attention 与调度开销；当前单次 A/B 没有显示稳定赢家，也不能代替真实 7.2B 模型的官方 `vllm bench` 验收。
3. **诊断高并发 cache hit 崩塌**：核查缓存容量、驱逐、抢占及 prefix 复用；历史 RTX 在 c64 从约 74% 降至 9.72%，当前 B300 则在 c128 降至 33.00%，两者不能混为同一容量拐点。
4. **分别记录 prefill 和 decode 收益**：同时观察冷启动首轮 TTFT、后续 TTFT、TPOT 和吞吐，不能只优化其中一个。
5. **保留 Cutlass 作为独立 A/B**：B300 FlashRWKV2 路径上只有约 3%–4% 吞吐收益，它不是 Inductor 大幅收益的替代解释。
6. **不要把合并 RWKV r/k/v 当成已证实方向**：bux 同样分开 r/k/v 投影；既有 A100 trace 也显示 GEMM、attention 和 host/copy overhead 都需要分析。
